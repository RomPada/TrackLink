# TrackLink

Версія: **v0.4.0**

TrackLink — це невеликий self-hosted сервіс редиректів та аналітики переходів для Telegram, Facebook, Instagram, реклами, email-кампаній, Patreon-посилань та інших джерел трафіку.

Основний README англійською: [README.md](./README.md)  
Історія версій: [PATCHLIST.md](./PATCHLIST.md)  
План розвитку: [ROADMAP.md](./ROADMAP.md)

Короткі tracking-посилання тепер виглядають так:

- `https://твій-домен.com/tg`
- `https://твій-домен.com/instagram`
- `https://твій-домен.com/fb`

Усі вони можуть вести на одну й ту саму кінцеву адресу, але статистика зберігається окремо для кожного slug.

## Можливості

- необмежена кількість tracking-посилань;
- англійська мова інтерфейсу за замовчуванням із перемикачем EN / UA на сторінці входу, в адмінці та демо;
- вікна підтвердження перед видаленням посилань і груп;
- публічна сторінка `/demo` зі статичними тестовими даними без Supabase та адмінських прав;
- групи посилань для організації напрямів або кампаній, наприклад Patreon, GitHub і YouTube;
- короткий редирект `/[slug]` замість `/go/[slug]`;
- старі `/go/[slug]` залишені для сумісності;
- агрегована статистика за сьогодні, останні 7 днів, поточний місяць і весь час;
- у кожному періоді окремо показуються унікальні відвідувачі та всі переходи;
- така сама статистика для кожного окремого посилання;
- клікабельні блоки періодів із переглядом записів переходів;
- у записі видно анонімного відвідувача, дату/час, країну, посилання, кінцеву адресу та тип пристрою;
- визначення країни через геолокаційний header Vercel без збереження IP-адреси;
- агрегований графік активності за 14 днів;
- блок `System / Database`;
- створення, редагування, увімкнення/вимкнення та видалення посилань;
- захищена паролем адмінка;
- фільтрація основних preview-ботів і browser prefetch;
- IP-адреси не зберігаються;
- поле `referrer` більше не зберігається.

## Важливий крок при оновленні

Версія `v0.4.0` **не потребує нової міграції бази**. Якщо оновлюєшся з версії старішої за `v0.3.0`, врахуй, що `v0.3.0` розширює структуру бази групами посилань. При оновленні з будь-якої попередньої версії повторно виконай актуальну схему.

Після оновлення коду відкрий **Supabase -> SQL Editor** і повторно виконай актуальний файл:

```text
supabase/schema.sql
```

Скрипт розрахований і на оновлення вже існуючої бази TrackLink. Він зберігає зміни аналітики v0.2.0 та додає таблицю `link_groups` і поле `group_id` у посилання. Існуючі посилання не видаляються — спочатку вони залишаться у секції `Без групи`.

Старі записи переходів залишаться. Країни в них не буде, оскільки до v0.2.0 ця інформація не збиралася.

## 1. Створи Supabase-проєкт

1. Створи новий проєкт у Supabase.
2. Відкрий `SQL Editor`.
3. Виконай весь файл `supabase/schema.sql`.
4. У `Settings -> API Keys` створи або скопіюй **Secret key** виду `sb_secret_...`.
5. Скопіюй `Project URL`.

> Secret key не можна вставляти у клієнтський код або публікувати в GitHub.

## 2. Локальний запуск

Встанови залежності:

```bash
npm install
```

Створи `.env.local` на основі `.env.example` і заповни:

```env
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_SECRET_KEY=sb_secret_xxxxxxxxx
ADMIN_PASSWORD=твій-надійний-пароль
ADMIN_SECRET=довгий-випадковий-секрет
```

Для `ADMIN_SECRET` використовуй випадковий рядок довжиною від 40 символів.

Запусти:

```bash
npm run dev
```

Адмінка:

`http://localhost:3000/admin`

Публічне демо без підключення до бази та адмінських прав:

`http://localhost:3000/demo`

Тестове коротке посилання може виглядати так:

`http://localhost:3000/tg`

На localhost геолокаційного header Vercel немає, тому країна для локальних тестових переходів може відображатися як невідома/локальна.

## 3. GitHub

Створи репозиторій і завантаж код. Файл `.env.local` у GitHub не додавай — він виключений через `.gitignore`.

## 4. Vercel

1. У Vercel натисни `Add New -> Project`.
2. Імпортуй GitHub-репозиторій.
3. Додай у `Settings -> Environment Variables`:
   - `SUPABASE_URL`
   - `SUPABASE_SECRET_KEY`
   - `ADMIN_PASSWORD`
   - `ADMIN_SECRET`
4. Зроби deploy.

Після деплою посилання можуть виглядати так:

- `https://твій-проєкт.vercel.app/tg`
- `https://твій-проєкт.vercel.app/instagram`
- `https://твій-проєкт.vercel.app/facebook`

Пізніше можна підключити власний домен, наприклад `brand.link`, і отримати `https://brand.link/tg`.

## Групи посилань

Можна створити групи `Patreon`, `GitHub`, `YouTube` або будь-які інші та прив’язувати кожне tracking-посилання до однієї групи. Посилання можна переносити між групами в налаштуваннях. Видалення групи **не видаляє** її посилання — вони переходять у `Без групи`.

## Публічне демо

На сторінці входу є кнопка `Відкрити демо`. Маршрут `/demo` працює лише на статичних тестових даних: він не звертається до Supabase, не записує переходи та не надає адмінських прав. Це ознайомча версія інтерфейсу й аналітики.

## Агрегована статистика

TrackLink рахує статистику у PostgreSQL/Supabase views, тому для показу основних показників адмінка не повинна завантажувати всі сирі записи переходів.

Є чотири періоди:

- Сьогодні — календарна дата за часовим поясом `Europe/Kyiv`;
- Останні 7 днів — сьогодні та попередні шість календарних днів;
- За місяць — поточний календарний місяць;
- Всього — за весь час.

У кожному блоці є:

- `Унікальні`;
- `Всього переходів`.

Після натискання на блок відкриваються записи відповідного періоду. Для швидкості сторінка показує максимум 100 останніх записів, але окремо відображає повну кількість знайдених записів.

## Як рахується унікальний відвідувач

При першому зарахованому переході TrackLink ставить анонімний cookie `tt_visitor` з випадковим UUID. Наступні переходи з цього самого браузера використовують той самий ID.

Це **не абсолютна ідентифікація людини**. Інший браузер, інший пристрій, очищення cookie або деякі in-app browser-и можуть створити новий ID. Тому показник `Унікальні` є приблизним.

## Країна та приватність

На Vercel TrackLink читає platform header `x-vercel-ip-country` і записує у базу лише дволітерний код країни.

IP-адресу TrackLink не зберігає. Визначення країни за IP є приблизним. У записів, створених до v0.2.0, значення країни відсутнє.

## Превʼю соцмереж

Telegram, Facebook, LinkedIn та інші сервіси можуть автоматично відкривати URL, щоб створити preview. Такі запити не повинні рахуватися як реальні кліки. У `lib/bots.ts` є фільтр основних preview/crawler user-agent-ів, а HEAD-запити ігноруються.

## Структура даних

`link_groups` — необов’язкові групи посилань.

`links` — tracking-посилання з необов’язковим `group_id`.

`clicks` — кожен зарахований перехід:

- `link_id`;
- анонімний `visitor_id`;
- `country_code`;
- user-agent;
- дата і час.

Старе поле `referrer` видаляється у v0.2.0.

## Зарезервовані slug

Оскільки короткі посилання тепер знаходяться прямо в корені домену, не можна створювати tracking-посилання з такими slug:

- `admin`
- `login`
- `demo`
- `go`
- `api`
- `_next`

## Усунення помилок

### Після оновлення адмінка показує помилку Supabase

Повторно виконай актуальний `supabase/schema.sql` у Supabase SQL Editor. Для v0.3.0 потрібна таблиця/поле груп, а також поля й views, додані у v0.2.0.

Також перевір:

- `SUPABASE_URL` у `.env.local`;
- `SUPABASE_SECRET_KEY` має бути серверним Secret key виду `sb_secret_...`, а не `sb_publishable_...`.

Після зміни `.env.local` перезапусти `npm run dev`.

### Hydration mismatch у режимі розробки

Якщо в повідомленні є сторонні атрибути на кшталт `bis_skin_checked`, `bis_register` або `__processed_...`, їх додає розширення браузера до HTML ще до запуску React. Перевір сторінку в режимі інкогніто або тимчасово вимкни розширення на `localhost`.
